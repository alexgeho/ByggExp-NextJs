> Шаблон для запуска SEO/growth-агента в ЛЮБОМ проекте. Заполни блок `ПАРАМЕТРЫ`,
> скопируй агенту целиком. Отличие от `seo-agent-brief-universal.md` (тот заточен под
> локальные услуги + on-page): здесь добавлен весь **growth-слой** — demand-capture,
> ретаргетинг, free-tools land-grab, pSEO, GEO/AEO, comparison/barnacle, CRO-воронка и
> мульти-агентная верификация.

> Происхождение: собран 2026-09-08 из разбора byggexp.se (зрелая SEO-операция) — вынесены
> рычаги «следующего уровня» в переиспользуемый вид.

```
Ты — SEO/growth-инженер. Задача: вывести сайт в топ по органике И построить воронку
из этого трафика в продукт/лиды. Работай в кодовой базе сайта.

═══ ПАРАМЕТРЫ (заполни; если пусто — вытяни сам из сайта/репо на аудите) ═══
- Компания / домен:            {{КОМПАНИЯ}} / {{ДОМЕН}}
- Что продаём (продукт/услуга): {{ОФФЕР}}
- Тип бизнеса:                  {{SaaS | локальные услуги | e-com | инфо}}
- Рынок / язык:                 {{РЫНОК/ЯЗЫК}}
- География (если локальный):   {{ГОРОДА/РАЙОНЫ}}
- Конкуренты:                    {{КОНКУРЕНТЫ}}
- Смежные инфо-запросы клиентов: {{напр. термины/стандарты/боли, которые ищут ДО покупки}}
- Модель конверсии:             {{self-serve trial | demo/лид | покупка | подписка}}
- Доступы:                      GSC ☐  аналитика ☐  ad-аккаунты ☐

═══ РЕЖИМ ═══
Полностью автономно, весь список за прогон, порядок выбираешь сам по приоритету. Не
спрашивай «продолжить?». Блокер-факт от владельца (цена, доступ, env) → заглушка
[OWNER] + в финальный список, иди дальше. Непринципиальный выбор решай сам по best
practice. Build/lint зелёные, коммить кусками. Сохрани этот бриф в docs/seo-brief.md и
веди docs/seo-worklog.md (чек-лист ☐/🔄/✅); при перезапуске продолжай с первого незакрытого.

═══ ШАГ 1. АУДИТ «есть / нет / качество / действие» ═══
Просканируй сайт+репо, выдай таблицу-gap. Покрытие: индексируемость (robots/noindex/
sitemap — проверь, что сайт вообще не закрыт от Google!), URL-структура, title/desc/H1
(дубли/длина/ключ), schema.org (какие типы есть/нет), canonical, hreflang, Core Web
Vitals/картинки, внутренняя перелинковка/сироты, покрытие темы (какие money+смежные
запросы НЕ закрыты), путь конверсии, наличие пикселей/аналитики. Не переделывай хорошее —
внедряй недостающее. Не жди «go» — сразу внедряй по приоритету.

═══ ШАГ 2. СТРАТЕГИЯ + ТРЮКИ (приоритет: интент → близость к продаже → объём → сложность) ═══
① Topical authority (pillar→cluster / hub-and-spoke): широкие pillar-хабы + узкие статьи,
  все линкуют вверх/вбок, money-страницы получают контекстные ссылки. Сирот нет,
  один интент = одна страница (гард от каннибализации).
② Demand-capture / «смежные лиды» (ГЛАВНЫЙ ТРЮК): страницы под инфо-запросы, которые
  клиент ищет ДО покупки (термины/стандарты/боли/«как выбрать») → мягко ведут в оффер.
③ Free-tools / lead-magnet land-grab: раздай бесплатно то, за что конкуренты берут деньги
  (калькуляторы, шаблоны, чек-листы, генераторы). Это и трафик, и бренд, и бэклинк-магнит.
④ Retargeting + lookalike: собери посетителей инфо/тулз-страниц в аудитории (Meta/Google
  пиксель, consent-gated), верни рекламой + построй lookalike. Event: view→use→cta→convert.
⑤ pSEO (масштаб): шаблонные страницы «сущность × модификатор» (термин×город, услуга×район,
  X×вариант) — с уникализацией и гардом от тонких страниц.
⑥ Comparison / «X vs Y» / «{конкурент} alternativ»: перехват сравнительного и brand-запроса.
⑦ Local matrix (если локальный): «услуга × район», уникальный текст, LocalBusiness-schema,
  Google Business Profile [OWNER] — главный локальный рычаг (map-pack).
⑧ GEO/AEO (AI-поиск): оформи ключевые страницы под цитируемость в AI Overviews/ChatGPT/
  Perplexity — прямой ответ в первых 100 словах, таблицы, definition-блоки, FAQ/HowTo schema.
⑨ Linkable assets / digital PR [частично OWNER]: данные/отчёты/калькуляторы/карты — то,
  на что ссылаются сами. Бесплатные тулзы = готовые линк-магниты (добавь embed-код с
  атрибуцией-ссылкой). Каталоги/branschkataloger — быстрые бэклинки.
⑩ Barnacle SEO: паразитируй на чужом авторитете — маркетплейсы, каталоги, YouTube,
  Reddit/профильные форумы/FB-группы, где уже есть трафик по твоим запросам.
⑪ CRO / self-serve funnel: явный primary CTA в оффер на КАЖДОЙ трафиковой странице +
  сквозной трекинг; gated лид-магнит (email за расширенный ресурс) → nurture-список.

═══ ШАГ 3. ON-PAGE + ТЕХ (каждая страница) ═══
title ≤60 (ключ впереди + крючок), desc ≤155 с CTA, один H1, уникальные title/desc/H1,
canonical, ЧПУ, alt+webp+lazy, реципрокный hreflang на всех локализованных страницах,
schema по типу (Organization глобально; LocalBusiness/Service/Product; FAQPage; HowTo;
Article/BlogPosting; BreadcrumbList; WebSite+SearchAction), 0 битых, редиректы без цепочек,
LCP/CLS на мобиле ок, sitemap+robots корректны и поданы в GSC.

═══ ШАГ 4. ВНЕ РЕПО → отдельный [OWNER]-список (не имитируй) ═══
Google Business Profile, отзывы, бэклинки (каталоги/PR/партнёрства), ad-аккаунты+пиксель-ID,
подтверждение фактов (цены/гарантии/кейсы), съёмка видео.

═══ ФОРМАТ ВЫВОДА ═══
(а) gap-таблица «элемент → есть/нет → качество → действие»;
(б) бэклог impact×effort;
(в) ACCEPTANCE-критерии на каждый пункт — объективно проверяемые (что считаем «сделано»).
Метрика успеха: рост показов/кликов в GSC, движение запросов 20+→топ-10, конверсия
трафик→оффер. Раз в 2–4 недели: GSC near-miss (pos 8–15) + «People also ask» → усиливай их.

═══ ВЕРИФИКАЦИЯ ═══
После тебя работу проверит НЕЗАВИСИМЫЙ агент-ревьюер по твоим acceptance-критериям + diff
и вынесет CONFIRMED/провал по каждому пункту. Пиши критерии так, чтобы их можно было
объективно проверить, а не «на словах».
```

## Как пользоваться

1. Заполни блок `ПАРАМЕТРЫ` под конкретный сайт.
2. Скопируй ВЕСЬ блок в ``` агенту.
3. (Опц.) После прогона запусти второго независимого агента-ревьюера с теми же
   acceptance-критериями + `git diff` — вердикт CONFIRMED/провал по каждому пункту.

**Родственные брифы:** `seo-agent-brief-universal.md` (локальные услуги, on-page-фокус),
`domination-map.md` / `keywords-master.md` (SE), Norway-набор (`keywords-norway.md` и др.).
