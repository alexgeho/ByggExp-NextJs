## 1. Режим работы: автономно, без остановок
1. Работай **полностью автономно**. Не спрашивай разрешения, не пиши «продолжить?/go?». Считай, что «да, продолжай» сказано на всё, что входит в задачу.
2. Выполни **ВСЕ пункты до конца** за один прогон, шаг за шагом, не останавливаясь между ними.
3. **Порядок выбираешь сам** по стратегии (тех-фундамент → money-ядро → location-матрица → смежные кластеры → блог). Не жди «теперь шаг 2, теперь шаг 3».
4. **Не блокируйся.** Нужен факт только от владельца (цена, гарантия, сертификат, доступ) — ставь заглушку `[ПОДТВЕРДИТЬ У ВЛАДЕЛЬЦА]`, заноси в список и **иди дальше**.
5. Непринципиальный выбор (нейминг URL, порядок секций, формулировка) — **решай сам** по best practice. Вопросы — одним списком **в конце**.
6. Между шагами не жди ввода: закончил → строка в лог «✅ X, дальше Y» → сразу делаешь Y.
7. Прогресс важнее идеала: лучше все пункты на 90% + список доработок, чем один идеально и застрять.
8. Не ломай сборку: после правок — build/lint зелёные. Коммить логическими кусками (режим push уточни один раз в начале, дальше не переспрашивай).

## 2. Сохрани задачу для будущих прогонов
Перед стартом сохрани этот бриф в `docs/seo-agent-brief.md` (постоянная инструкция, перечитывай в начале каждой сессии) и заведи `docs/seo-worklog.md` как чек-лист всех шагов со статусами (☐ / 🔄 / ✅). Веди его по ходу. При перезапуске — прочитай оба файла и продолжай автономно с первого незакрытого пункта.

## 3. Сначала аудит-«gap analysis» (что есть / чего нет)
Просканируй репозиторий и сайт и составь таблицу **«элемент → есть? → качество → действие»**. Не переделывай хорошее — внедряй недостающее. Покрытие:
- структура URL и существующие страницы (услуги/районы/статьи);
- title / description / H1 (дубли, длина, наличие ключа);
- schema.org (какие типы есть/нет);
- sitemap.xml, robots.txt, canonical, индексируемость;
- Core Web Vitals, мобильность, изображения (webp/alt);
- внутренняя перелинковка и страницы-сироты;
- локальные сигналы (NAP-консистентность, LocalBusiness-schema);
- покрытие темы (какие money- и смежные запросы НЕ закрыты).

Выдай отчёт + план, но **не жди подтверждения** — сразу внедряй по приоритету.

## 4. Стратегия (приоритет сверху вниз)

**A. Локальное SEO — главный рычаг.**
- Google Business Profile → задача владельцу №1 (map-pack). Проверь NAP во всех местах сайта + в schema.
- Внедри `LocalBusiness` (или точный подтип: `RoofingContractor`, `Plumber`, `Electrician`…) на главной/контактах: name, address, geo, telephone, areaServed, openingHours, priceRange, sameAs.

**B. Матрица «услуга × район».**
Отдельная location-страница под каждый район с **уникальным** текстом (не копипаст-шаблон): местные ориентиры, специфика, локальный CTA. URL `/{{tjänst}}-{{ort}}` или `/{{ort}}/{{tjänst}}`. Покрыть больше районов, чем конкурент.

**C. Money-страницы услуг.**
На каждую услугу: H1 с ключом, интро, «что входит», процесс по шагам, цена/вычеты (ROT и т.п.), FAQ + `FAQPage` schema, CTA + форма/телефон. Отдельные под `{{tjänst}} kostnad`, `{{tjänst}} pris`.

**D. Бренд/нишевый угол.** Если домен намекает на нишу (`{{NISCH-VINKEL}}`) — займи её как дифференциатор.

## 5. SEO-архитектура по смежным запросам (topical authority)
Строй **семантическую архитектуру** вокруг всей темы: Google ранжирует тематический авторитет всего домена, внутренние ссылки перекачивают вес на money-страницы.

**Модель pillar → cluster (hub-and-spoke):** широкие pillar-хабы + узкие статьи вокруг, все линкуют вверх и вбок; money-страницы получают контекстные ссылки с ключевыми анкорами. Сирот нет.

**Как вывести смежные темы для любой ниши:**
- Компоненты/части объекта услуги (под-сервисы рядом).
- Проблемы/симптомы клиента (top-of-funnel «боль»).
- Материалы/варианты/сравнения (X vs Y vs Z, сроки службы, за/против).
- Решенческие/деньги (сколько стоит, вычеты/субсидии, разрешения, гарантия, «как выбрать исполнителя»).
- Сезонное (по календарю).
- Энерго/эко/тренды ниши.

**Приоритет:** интент → близость к продаже → объём → сложность. Порядок: money-ядро → bottom-funnel решенческие → проблемы/симптомы → компоненты → материалы → сезонное.

**Правила против размытия веса:** один интент = одна страница (проверяй каннибализацию); информационное ≠ коммерческое; каждая страница линкует на 2–3 релевантные и получает входящие; анкоры по ключу без переспама.

## 6. On-page требования (каждая страница)
- `title` ≤ ~60 симв.: точный ключ впереди + локальный/крючок-хвост.
- `meta description` ≤ ~155 симв. с ключом и CTA.
- Ровно один `H1` с ключом; логичная иерархия H2/H3.
- Уникальные title/description/H1 (проверь дубли).
- Canonical, ЧПУ-URL, alt у картинок (ключ+гео), внутренняя перелинковка услуга↔район↔статья.
- Schema по типу: LocalBusiness (глобально), Service/FAQPage (услуги), Article (блог), BreadcrumbList.

## 7. Технический SEO чек-лист
- sitemap.xml + robots.txt корректны, sitemap в GSC.
- Все ключевые страницы индексируемы (нет случайного noindex); проверь Coverage/Pages.
- Core Web Vitals: webp + размеры + lazy-load; LCP/CLS на мобиле.
- Мобильность, HTTPS, нет битых ссылок/404, редиректы без цепочек, быстрый TTFB.

## 8. Вне репозитория — задачи владельцу (не имитируй, отдельным списком)
- Google Business Profile: создать/заполнить, категория, фото, районы.
- Отзывы: собрать (сильнейший локальный + trust сигнал).
- Бэклинки: местные каталоги, branschkataloger, партнёрства.
- Подтвердить факты: цены, гарантии, опыт, сертификаты, кейсы «до/после».

## 9. Метод и измерение
1. Аудит → план (карта URL) → **сразу** реализация по приоритету (без ожидания «go»).
2. После каждого этапа: build/lint зелёный + строка в worklog.
3. Раз в 2–4 недели: GSC → отчёт Queries → near-miss (позиции 8–20) и случайные показы = темы для новых/усиленных страниц. Autocomplete / «People also ask» / «Related searches» для long-tail и FAQ.
4. Метрика успеха: рост показов/кликов, движение запросов 20+→топ-10, вход в map-pack.
5. E-E-A-T: реальный опыт/лицензии в Om oss, кейсы до/после, консистентный NAP, sameAs на GBP/соцсети.

**Суть одной фразой:** разбей на шаги, сохрани план в файл, проведи аудит «что есть/чего нет» и внедри всё недостающее — все шаги подряд, сам, без остановок и вопросов между ними; блокеры обходи заглушками и копи в финальный список; порядок и непринципиальные решения выбирай сам.
