# ТЗ / Плейбук: фото-обложки для блога (генерация → разнообразие → расфасовка → релевантность)

Переносимый метод для ЛЮБОГО контентного сайта, где много статей без картинок
(или с текстовыми заглушками). Проверено на byggexp.se (~226 статей). Отдавай
этот файл агенту в целевом репозитории — он самодостаточен.

Цель: у каждой статьи — релевантная фото-обложка; в сетке блога картинки
**разнообразные**, **не монотонные** и **правильно расфасованы** (людей немного и
не «столбиком»).

---

## 0. Что нужно один раз

- **Replicate-аккаунт** + токен `REPLICATE_API_TOKEN` в gitignored `.env.admin`
  (или `.env`). Кредит от $10 (billing: replicate.com/account/billing). FLUX-dev
  ≈ $0.03/картинка, schnell ≈ $0.003, pro ≈ $0.04. Дефолт — **dev**.
- **Скрипт `scripts/gen-image.js`** (скопировать из byggexp-репо). Умеет:
  `node scripts/gen-image.js "<prompt>" --out public/<path>/<slug> --ar 16:9 --model dev --width 1000`.
  Внутри: читает `.env.admin`, зовёт Replicate FLUX, poll + retry на 429, качает
  → `sharp` → webp. Модели: schnell|dev|pro.
- Понять, **где хранятся обложки** и как статья ссылается на cover (путь вида
  `/landing/blog/<slug>.webp` или аналог). Роутинг фото описан в разделе 6.

---

## 1. Инвентаризация (что покрываем)

1. Собери список slug'ов статей, которым нужна обложка (нет картинки / текстовая
   заглушка / общий сток). Для каждого достань **title + excerpt + tag** (парсинг
   контент-файлов или CMS).
2. Достань **реальный порядок ленты** блога (как рендерится сетка, обычно
   `publishedAt` desc) — он нужен для расфасовки людей по рядам. Проще всего:
   поднять сайт локально и вытащить порядок slug'ов из HTML листинга.

---

## 2. Таксономия сцен (ключ к разнообразию)

Не давать агентам свободу — иначе всё сведётся к «каска на столе». Заданные типы:

- `person-solo` — ОДИН рабочий делает именно эту работу (кладёт плитку, варит,
  тянет проводку, штукатурит, кроет крышу, размечает). На объекте, НЕ за столом.
- `person-group` — 2–3 человека вместе по теме (бригада, рукопожатие по договору,
  планёрка).
- `object-material` — макро материала/инструмента/узла. БЕЗ людей.
- `documents-drawings` — чертёж/чек-лист/договор/бумаги на столе. БЕЗ людей.
- `no-people-site` — стройка/здание/конструкция по теме. БЕЗ заметных людей.
- `tablet-screen-or-detail` — планшет/ноут с данными ИЛИ макро-деталь. БЕЗ
  заметных людей.

Расширяй под нишу: для бетонных работ добавь «заливка плиты», «армирование»,
«опалубка», «затирка», «бетононасос», «пробы бетона», «трещины/дефекты».

---

## 3. Правила расфасовки и разнообразия (ГЛАВНОЕ)

Сетка блога обычно **3 колонки**. Правила:

1. **В каждом ряду (3 обложки) — максимум 1 картинка с людьми** (соло ИЛИ группа).
2. **Люди не должны стоять столбиком** — картинку с человеком ставим в
   разные колонки по рядам (ротация 0→1→2→0…).
3. **Людей немного суммарно** — целься ~**20–33%** обложек с людьми, остальное
   объекты/материалы/чертежи/стройки/детали.
4. Чередуй `person-solo` и `person-group`.
5. **Квота на «офис/стол»**: сцены со столом/ноутом/планшетом — только если статья
   реально про софт/учёт/экономику. Иначе — БАН (см. раздел 4).

Алгоритм назначения сцен (по реальному порядку ленты, учитывая, что часть
обложек уже фиксирована — продуктовые мокапы и т.п. считаем «без людей»):

```
personCounter = 0; npIdx = 0
для каждого ряда из 3 slug'ов:
  fixedPeople = сколько в ряду уже-людных фиксированных обложек
  budget = max(0, 1 - fixedPeople)
  assignable = наши slug'и в этом ряду
  если budget>0 и assignable: выбрать 1 (колонка = personCounter%3, иначе первый)
    → ему person (solo если personCounter чётный, иначе group); personCounter++
  остальным assignable → неперсонная сцена из пула [object, documents, site, tablet],
    циклично npIdx++
```

## 4. Жёсткие баны (иначе вылезет монотонность)

- ❌ «Каска лежит на деревянном столе» (главный штамп).
- ❌ «Планшет/ноут/калькулятор на столе» — КРОМЕ статей буквально про софт/учёт
  времени/счета/экономику-дашборд.
- ❌ Генерик «офис с чертежами на столе».
- ❌ Читаемый/кривой текст на картинке — писать в промпте «blur any text /
  illegible / no text no watermark» (FLUX всё равно иногда лепит абракадабру —
  на тамбнейл-размере терпимо, вблизи фейк; это потолок модели).
- ❌ Объекты «в воздухе» / левитация, деформированные люди.

Каждый промпт заканчивать: `photorealistic, professional, no text no watermark`.
Промпты — на английском (FLUX лучше понимает). Nordic/локальный контекст под нишу.

## 5. Пайплайн (мульти-агент)

Три фазы, каждая — параллельные агенты (workflow) + локальный пул-раннер генерации.

**Фаза A. Промпты.** N агентов, каждый читает файл `{slug,title,tag,scene}` и
пишет ОДИН FLUX-промпт: по теме статьи + строго заданный тип сцены + баны.
Возвращает `{slug, prompt}` (структурный вывод). Собрать промпты из
`journal.jsonl` прогона.

**Фаза B. Генерация.** Пул-раннер (concurrency ≤6) зовёт `gen-image.js` на каждый
`{slug,prompt}` → `/…/<slug>.webp`. ⚠️ При кредите <$5 или concurrency >5 Replicate
кидает 429 — гнать CONC≤6 + retry, упавшие добить последовательно.

**Фаза C. Аудит релевантности (vision-агенты).** N агентов, каждый **Read'ит саму
картинку** + текст статьи, возвращает `{score 1-5, sceneLabel, clicheDesk,
issues[], suggestedScene}`. Свести: перегенерить те, где `score≤2`, `clicheDesk`,
off-topic, или (для максимума) `score==3`. Взять `suggestedScene` как направление,
пересчитать расфасовку (раздел 3), перегенерить только помеченные.

Повторять C→A→B пока не устроит. Все три фазы уже отлажены в byggexp-репо
(workflow-скрипты в истории сессии).

## 6. Подключение обложек в сайт (без правки каждой статьи)

Единый источник правды — один файл-список:

```ts
// src/content/photo-covers.ts
export const PHOTO_COVER_SLUGS = new Set<string>([ '<slug>', ... ]);
```

- Резолвер обложек (напр. `withGeneratedCover` в `code-articles`) роутит:
  если `PHOTO_COVER_SLUGS.has(slug)` → `coverImageUrl = /…/blog/<slug>.webp`
  (+ `seoImageUrl` для OG). Независимо от старого манифеста заглушек.
- Если есть генератор текстовых карточек — он должен **пропускать**
  `PHOTO_COVER_SLUGS`, чтобы не затирать фото.

Так фото показывается сразу, без 200 правок в статьях, и не регенерится поверх.

## 7. Приёмка (QA)

- Монтаж всех новых обложек (sharp-грид 4 колонки) — просмотреть глазами: брак,
  деформации, оффтоп, повторы.
- Монтаж **реального порядка ленты в 3 колонки** — проверить «≤1 человек в ряд» и
  что люди не столбиком.
- tsc + build зелёные. Проверить пару статей: `og:image` → правильный webp.
- Деплой, проверить прод.
