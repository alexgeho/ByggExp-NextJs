# ByggExp SMM — дизайн-система (живой документ)

Правила для всего, что уходит в соцсети: картинки постов, обложки, видео (Reels/Shorts/YouTube).
Сайт — отдельный файл: `DESIGN-SYSTEM.md` в корне репо. Общие принципы: `~/ui-principles.md`.

**Как работаем:** каждая правка владельца → новое правило S-N ниже (дата, что, почему, где в коде) → правка генератора → только потом новый дизайн. Перед показом владельцу — пройти чек-лист в конце.

## Правила
**S1 · 2026-10-19 · Только реальные экраны продукта/сайта.** Никаких слайдов-заглушек и нарисованных интерфейсов. Почему: слайд-видео владелец забраковал.

**S2 · 2026-10-19 · Экран целиком, углы не обрезаны.** На общем плане скрин виден полностью; обрезка допустима только при наезде камеры.

**S3 · 2026-10-19 · Видео: камера, не рывки.** Сцена: общий план → плавный наезд на главное место (кнопка/колонка/меню) → держит → отъезд. Smootherstep, субпиксельно (`resize(box=…)` на 2x-сцене). Каждое видео в 16:9 и 9:16.

**S4 · 2026-10-19 · Картинка поста = заголовок + скрин + лого.** Формат 4:5. Сверху заголовок в 2 строки (белая — вопрос/тема, голубая — выгода), в центре скрин, внизу лого + byggexp.se. Почему: голые вырезки с сайта в ленте не читаются.

**S5 · 2026-10-19 · Скрин крупный и читаемый.** Вырезать только главный блок (результат калькулятора, готовый документ), не всю форму; без пустых полей и пустого низа карточки. Текст скрина на телефоне читается без зума. Скрины только 2x.

**S6 · 2026-10-19 · Субтитры видео — на плашке**, не обводкой поверх интерфейса.

**S8 · 2026-10-19 · Каждое число на картинке объяснимо с картинки.** Если показан результат расчёта — рядом видны входные данные (напр. timlön 220 × 2 timmar = 440). Код: в `make_posts.py` бокс может быть списком — вырезки ставятся стопкой (ввод сверху, результат снизу). Почему: «440 kr» без ввода непонятно, откуда.

**S9 · 2026-10-19 · Перед показом — всегда агент-критик.** Отдельный агент без контекста получает только готовые картинки/кадры + текст поста и как зритель из ленты (шведский хантверкар) отвечает: о чём пост за 2 секунды? понятно ли каждое число и откуда оно? что читается плохо или лишнее? нарушены ли правила S1–S8? Всё, что критик не понял, — исправить и прогнать критика снова. Владельцу показывать только после «чисто». Почему: владелец не должен сам находить непонятные места (как «440 kr» без ввода).

**S10 · 2026-10-19 · Низ картинки (футер) — выбирает владелец.** Варианты в `make_posts.py` (FOOTERS): `row` лого+сайт в строку · `small` без лого, мелкий сайт · `stack` лого, сайт под ним · `right` сайт справа голубым. Сравнение: `python3 make_posts.py <скрины> --footers` → 04-ob-*.jpg. После выбора — записать сюда и поставить FOOTER.

**S11 · 2026-10-19 · Числа в примерах — реалистичные для отрасли.** Timlön ≈ средняя по стройке (SCB byggindustri апрель 2026 ≈ 232 kr → берём 230), не случайные дефолты. Скрины — формы, заполненные как реальный пользователь (puppeteer, `posts/shot-tools.mjs`, нужен puppeteer-core), без серых плейсхолдеров. Одна история на картинке: если ÄTA → faktura, то в счёте те же строки и суммы, что в ÄTA.

**S7 · Текст.** Шведский, без кириллицы; только факты из `docs/seo/product-facts-verified.md`; ссылки с UTM.

## Чек-лист перед показом
1. Реальный экран, углы целы на общем плане (S1, S2).
2. Есть заголовок 2 строки + лого внизу, формат верный (S4).
3. Скрин читается на телефоне, нет пустых областей (S5); каждое число объяснимо с картинки (S8).
4. Видео: нет рывков, есть наезд/отъезд, оба формата (S3); субтитры на плашке (S6).
5. Текст: шведский без кириллицы, факты проверены, UTM (S7).
6. Посмотреть результат картинкой до отправки владельцу.
7. Агент-критик прошёл и ответил «чисто» (S9).
